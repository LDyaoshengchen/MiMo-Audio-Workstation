## 已复现问题

### 1. 高优先级：生成中切换画板，结果会进入错误画板

- 条件：在画板 A 启动单节点音频克隆，请求尚未完成时切到画板 B。
- 结果：A 的请求返回后，产物被追加到当前 B 的节点列表，连线仍引用 A 中的源节点；保存也面向当前画板 B。
- 影响：产物串入其他画板，出现无效连线，A 中缺失对应结果。探针使用模拟响应和内存保存，未写入用户文件。
- 代码：[结果追加](D:/mimo-tts-studio-main/src/studio/synthesisActions.ts:31)、[请求后追加](D:/mimo-tts-studio-main/src/studio/synthesisActions.ts:134)、[当前画板保存](D:/mimo-tts-studio-main/src/studio/StudioApp.tsx:1954)。
- 建议：将任务绑定到启动时的画板 ID 和源节点 ID；完成后保存回原画板，不直接追加到当前画板。删除源节点时也要定义取消或结果归属规则。

### 2. 中优先级：清空行参考音频后，生成仍使用旧角色音频

- 条件：在综合工作台应用含参考音频的角色，再清除某行左侧参考音频。
- 结果：界面清除了行字段，但节点级参考音频仍保留；生成时回退到节点音频，探针实际发送了 `old-role.wav`。
- 影响：界面显示没有参考音频，后台仍按旧音色生成，可能浪费调用。
- 代码：[清空行](D:/mimo-tts-studio-main/src/components/nodes/IntegratedStudioNode.tsx:323)、[生成回退](D:/mimo-tts-studio-main/src/studio/synthesisActions.ts:329)。
- 建议：区分“继承节点参考音频”和“用户明确清空”，并使界面展示与实际请求一致。

### 3. 中优先级：旧 Voice ID 会覆盖新上传或拖入的参考音频

- 条件：先应用包含 Voice ID 的角色，再在综合工作台某行上传或拖入另一段参考音频。
- 结果：节点仍保留旧 Voice ID；请求被强制切换到 `voiceId` 模式，未发送该行的新参考音频。探针结果为 `voiceId=old-voice-id`、`newReferenceSent=false`。
- 影响：新音频在界面出现，但不参与合成，表现为更换音频不生效。此问题仅在节点仍带 Voice ID 的组合条件下发生。
- 代码：[角色应用](D:/mimo-tts-studio-main/src/components/studio/RoleVoiceLibrary.tsx:115)、[行生成](D:/mimo-tts-studio-main/src/studio/synthesisActions.ts:351)、[Voice ID 强制覆盖](D:/mimo-tts-studio-main/src/utils/providerConfig.ts:27)。
- 建议：明确参考音频与 Voice ID 的优先级；更换行参考音频时允许覆盖节点级 Voice ID，或在界面明确提示当前不会使用音频。

### 4. 中优先级：部分历史版本无法收到实际新发布版本的更新提示

- 条件：安装版本为历史上的 `0.8.39`，GitHub 最新发布为 `v0.8.5`。
- 结果：数字版本比较认为 39 大于 5，返回 `updateOffered=false`，界面报告已是最新。
- 影响：这些旧版本用户无法通过更新检测获知后来发布的 v0.8.4/v0.8.5。0.8.4 → 0.8.5 的正常升级比较不受影响。
- 代码：[版本比较](D:/mimo-tts-studio-main/electron/desktop-controls.cjs:6)、[更新状态判定](D:/mimo-tts-studio-main/electron/desktop-controls.cjs:99)。
- 建议：制定兼容历史编号的迁移策略，后续采用严格递增版本；不要仅改为任意版本不同就提示升级，以免正常回退版本被误报。
